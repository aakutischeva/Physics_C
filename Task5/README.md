# Задание 2.5. Простейшие операции с матрицами


Проект содержит обязательные функции `alloc2d`, `free2d`, `vabs`,
`scal_prod`, `fill`, `matrix_prod`, `show2d`, их объявления в `linal.h`,
демонстрационную программу и тесты. Дополнительно предусмотрена функция
`matrix_prod_rect` для умножения произвольных согласованных прямоугольных
матриц.

## Файлы

| Файл | Назначение |
|---|---|
| `linal.h` | Прототипы функций библиотеки и пояснение размеров матриц |
| `linal.c` | Реализация выделения памяти и операций линейной алгебры |
| `main.c` | Демонстрация умножения матриц и операций с векторами |
| `tests.c` | Модульные тесты: основные и граничные случаи |
| `run_tests.sh` | Сборка и автоматическая проверка в Bash/Git Bash |

## Сборка и запуск

Нужен GCC с поддержкой C11. Команды выполняются в папке проекта `Task5`.
Проверено в среде GCC под Linux. Для Windows с MinGW и Git Bash используются
те же команды (расширение `.exe` приведено для удобства).

Сначала библиотека компилируется **отдельно** — в объектный файл:

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic -c linal.c -o linal.o
```

Затем выполняется компоновка демонстрационной программы:

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c linal.o -lm -o program.exe
./program.exe
```

Сборка и запуск модульных тестов:

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic tests.c linal.o -lm -o tests.exe
./tests.exe
```

Или одной командой (также проверяется точное содержимое демонстрационного
вывода):

```bash
bash run_tests.sh
```

Библиотеку можно скомпилировать и сразу из исходников:

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c linal.c -lm -o program.exe
```

Параметр `-lm` подключает математическую библиотеку; в некоторых системах
MinGW он не обязателен, но его присутствие допустимо.

## Результат демонстрации

Для матриц

\[
A=\begin{pmatrix}1&2&3\\4&5&6\end{pmatrix}, \qquad
B=\begin{pmatrix}7&8\\9&10\\11&12\end{pmatrix}
\]

получаем

\[
C=AB=\begin{pmatrix}58&64\\139&154\end{pmatrix}.
\]

Для векторов `u = (3, 4)` и `v = (1, 2)`:

- длина `u` равна `sqrt(3² + 4²) = 5`;
- скалярное произведение `u · v = 3·1 + 4·2 = 11`.

Программа печатает матрицы `A`, `B`, `C` и оба результата для векторов.

## Функции и математическое обоснование

### `double **alloc2d(int n1, int n2)`

Выделяет `n1` указателей на строки, затем для каждой строки — `n2`
элементов типа `double`. Благодаря `calloc` элементы первоначально равны
нулю. Каждый ряд выделяется отдельно: к элементу можно обратиться как
`a[i][j]`. Размеры должны быть положительными. При неудаче функция освобождает
уже выделенные строки и возвращает `NULL`.

**Важно:** это не один непрерывный прямоугольный массив из `n1*n2` чисел;
указатели на строки и строки выделены раздельно. Такое представление
соответствует использованию `double **` в сигнатурах пособия.

### `void free2d(double **a, int n1, int n2)`

Освобождает каждую из `n1` строк, затем массив указателей. Должны быть
переданы **те же размеры**, что при создании объекта; неверный `n1` нельзя
автоматически распознать по `double **`. Вызов с `NULL` ничего не делает.

### `double vabs(double *a, int n)`

Вычисляет евклидову норму вектора:

\[
\lVert a\rVert_2=\sqrt{\sum_{i=0}^{n-1}a_i^2}.
\]

Используется масштабированный алгоритм суммы квадратов. Он избегает
промежуточного переполнения `a[i]*a[i]` для больших компонент и потери
малых компонент при возведении в квадрат. Если **сама** норма не
представима в `double`, возвращаются `NAN` и `errno = ERANGE`.

### `double scal_prod(double *a, double *b, int n)`

Считает скалярное произведение:

\[
a\cdot b=\sum_{i=0}^{n-1}a_i b_i.
\]

Промежуточное накопление выполняется в `long double` с компенсацией ошибок
суммирования по Ноймайеру. Это уменьшает потери точности при сложении
величин очень разных порядков и при взаимном сокращении слагаемых. Однако
даже этот метод не гарантирует математически точного результата для любых
коэффициентов: конечная точность остаётся ограничением машинной арифметики.

### `void fill(double **a, int n1, int n2, double x)`

Заполняет всю матрицу значением `x` двумя вложенными циклами. Значения
`NaN` и бесконечности намеренно не допускаются, чтобы последующие операции
не получали недопустимые входные данные незаметно.

### `void matrix_prod(double **a, double **b, double **c, int n1, int n2)`

Выполняет поэлементное вычисление произведения по определению:

\[
c_{ij}=\sum_{k=0}^{n_2-1}a_{ik}b_{kj}.
\]

**Неоднозначность исходной сигнатуры.** В пособии эта функция принимает
только `n1` и `n2`, причём комментарием названы размеры **матрицы `a`**.
Для произвольного прямоугольного произведения третьего размера не хватает:
если `A` имеет размер `n1 × n2`, то `B` может иметь размер `n2 × p`, а
результат — `n1 × p` при произвольном `p`.

В рамках учебной функции принят явный договор:

- `A`: `n1 × n2`;
- `B`: `n2 × n1`;
- `C`: `n1 × n1`.

Так сохраняется прототип из пособия, и демонстрация использует именно его.
Это **не универсальное толкование сигнатуры**, а выбранное ограничение,
без которого невозможно определить размер результата.

### `void matrix_prod_rect(a, b, c, rows, inner, cols)`

Дополнительная универсальная функция для согласованных размеров:

- `A`: `rows × inner`;
- `B`: `inner × cols`;
- `C`: `rows × cols`.

Обе функции используют временную матрицу результата. Это позволяет
корректно выполнять умножение при совпадении выходной матрицы с входной,
когда их размеры совместимы (например, квадратные матрицы), и не менять
`C` при обнаруженной численной ошибке до завершения вычислений. Цена —
дополнительная память `O(rows * cols)`. Время вычислений
`O(rows * inner * cols)`.

### `void show2d(double **a, int n1, int n2)`

Печатает строки матрицы в стандартный вывод, числа — форматом `% .9g`.
Каждая строка матрицы занимает одну строку вывода.

## Обработка исключительных ситуаций

В C здесь не используются исключения в смысле `try/catch`: состояние
ошибки сообщается через `errno`.

| Ситуация | Результат |
|---|---|
| Размеры неположительные, указатель `NULL` | `errno = EINVAL` |
| Входной элемент `NaN` или `Infinity` в численной операции | `errno = EDOM` |
| Результат вне диапазона `double` (включая ненулевой результат, ставший нулём) | `errno = ERANGE` |
| Не удалось выделить память | `errno = ENOMEM` |
| Ошибка печати в `show2d` | ошибка `errno` от `printf`, при её отсутствии `EIO` |

`alloc2d` возвращает `NULL` при ошибке; численные скалярные функции
возвращают `NAN`; функции с типом `void` возвращаемого значения не имеют,
поэтому после вызова следует проверять `errno` (при успешном вызове
библиотечные функции его обнуляют, кроме `free2d(NULL)`).

Для `matrix_prod` и `matrix_prod_rect` выходная матрица остаётся неизменной
при обнаружении ошибочного входа, переполнения или невозможности выделить
временную память. При `fill` недопустимое значение `x` также оставляет
матрицу без изменений.

**Предусловия:** переданные массивы должны действительно содержать не
меньше заявленного числа строк и столбцов. По одному `double **` язык C
не позволяет узнать фактические границы выделенной памяти. Поэтому
указать завышенный размер — ошибка вызывающего кода, которую проверка
`NULL` и размеров не может надёжно предотвратить.

## Тестирование

`tests.c` охватывает:

1. выделение памяти, нулевую инициализацию, заполнение и освобождение;
2. норму обычного, нулевого, очень маленького и очень большого векторов;
3. скалярное произведение и компенсацию сокращающихся слагаемых;
4. произведение матриц `2×3` и `3×2`;
5. универсальное произведение `2×3` и `3×4`;
6. умножение квадратных матриц с записью результата в исходную матрицу;
7. случаи `1×1`, умножение на ноль, неверные размеры, `NaN`, `Infinity`,
   переполнение и потерю ненулевого результата при преобразовании в `double`.

В текущей конфигурации тестов: **7 групп, 46 проверок, 0 ошибок**.
Отдельная проверка `run_tests.sh` сравнивает полный консольный вывод с
ожидаемым: **PASS**.

Дополнительно выполнена сборка с `-fsanitize=address,undefined`: тесты
прошли при `ASAN_OPTIONS=detect_leaks=0`. Детектор утечек в данной среде
нельзя запустить из-за ограничений трассировки; это **не означает**, что
проверка утечек была проведена. Для MinGW возможность запуска AddressSanitizer
зависит от конкретной сборки компилятора.

## Переносимость и ограничения

- Целевая среда — **GCC C11**, в том числе MinGW/Git Bash. Проект не требует
  расширений GCC в исходном коде.
- Ширина и точность `long double` зависят от платформы. В MSVC он обычно
  имеет ту же точность, что `double`; выигрыш от расширенного накопления
  тогда может исчезнуть. Проверенная конфигурация — GCC.
- При округлении ненулевого результата в `0` функция сигнализирует
  `ERANGE`; некоторые приложения предпочитают принимать такое округление,
  но здесь потеря результата сделана явной.
- Операции предназначены для **небольших учебных матриц**. Для больших
  массивов эффективнее сплошное размещение данных и специализированные
  библиотеки линейной алгебры (например, BLAS).
- `show2d` предназначена для наглядного вывода, а не для сохранения
  результатов с полной точностью `double` (для этого обычно нужно
  не менее 17 значащих цифр).
