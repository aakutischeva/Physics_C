# Глава 2, задание 2.3 — статистические характеристики данных

Работа выполнена по разделу **2.3 «Статистика»** из пособия Е. Д. Маренкова «Программирование на Си для физических задач», с. 40–41.

## 1. Что требуется сделать

Имеется текстовый файл со столбцом чисел \(x_1,\ldots,x_N\). Программа должна вычислить:

1. Среднее значение \(\bar x\) — формула **(2.17)**.
2. Дисперсию \(\sigma^2\) и стандартное отклонение \(\sigma\) — **(2.18)**.
3. Коэффициент асимметрии \(s\) — **(2.19)**.
4. Коэффициент эксцесса \(k\) — **(2.20)**.

Дополнительные условия из пособия: **не хранить весь набор чисел в массиве**, сократить количество проходов по файлу и число используемых переменных. Для проверки рекомендован набор данных с известными характеристиками, в частности нормальное распределение.

Решение работает **за один последовательный проход по файлу**, использует постоянный объём памяти и не делает `rewind()` над входным файлом. Поэтому можно обрабатывать и обычный файл, и поток стандартного ввода (`stdin`).

## 3. Математические определения из пособия

**Среднее арифметическое**, формула (2.17):

\[
\bar x=\frac{1}{N}\sum_{j=1}^N x_j.
\]

**Дисперсия**, формула (2.18):

\[
\sigma^2=\frac{1}{N-1}\sum_{j=1}^N (x_j-\bar x)^2,
\qquad \sigma=\sqrt{\sigma^2}.
\]

**Коэффициент асимметрии**, формула (2.19):

\[
s=\frac1N\sum_{j=1}^N\left(\frac{x_j-\bar x}{\sigma}\right)^3.
\]

**Коэффициент эксцесса**, формула (2.20):

\[
k=\frac1N\sum_{j=1}^N\left(\frac{x_j-\bar x}{\sigma}\right)^4-3.
\]

**Важная особенность:** дисперсия в методичке делится на **`N-1`**, но асимметрия и эксцесс — на **`N`** с использованием *того же* \(\sigma\). Такое сочетание отличается от некоторых стандартных определений в статистических пакетах. В реализации взяты именно формулы **(2.17)–(2.20)**; «исправления смещения» для асимметрии и эксцесса не добавляются.

## 4. Как получаются все характеристики за один проход

Прямой способ требует сначала найти среднее, а затем ещё раз прочитать файл, чтобы посчитать степени отклонений от среднего. Здесь используется **потоковое обновление центральных моментов**: при поступлении очередного числа одновременно пересчитываются среднее и три суммы

\[
M_2=\sum(x_j-\bar x)^2,\quad
M_3=\sum(x_j-\bar x)^3,\quad
M_4=\sum(x_j-\bar x)^4.
\]

Пусть до добавления числа было `n−1` элементов, накопленные `mean`, `M2`, `M3`, `M4`, а новое значение равно `x`. Обозначим:

\[
\delta=x-\mathrm{mean},\qquad
d=\frac{\delta}{n},\qquad
t=\delta\,d\,(n-1).
\]

Новые значения вычисляются так (в правых частях для моментов используются **старые** значения `M2` и `M3`):

\[
\begin{aligned}
M_4'&=M_4+t d^2(n^2-3n+3)+6d^2M_2-4dM_3,\\
M_3'&=M_3+t d(n-2)-3dM_2,\\
M_2'&=M_2+t,\\
\mathrm{mean}'&=\mathrm{mean}+d.
\end{aligned}
\]

После окончания файла из сумм получаются статистики по формулам пособия:

\[
\sigma^2=\frac{M_2}{N-1},\qquad
s=\frac{M_3/N}{\sigma^3},\qquad
k=\frac{M_4/N}{\sigma^4}-3.
\]

Это развитие алгоритма Уэлфорда для центральных моментов третьего и четвёртого порядков. Время работы **`O(N)`**, дополнительная память **`O(1)`**. Для входных данных не используется массив, а файл прочитывается только один раз.

### Почему используется `long double` и вычитание первого числа

Суммирование исходных чисел и вычисление разности двух близких больших величин могут давать значительную погрешность. Например, среднее и дисперсию набора `1000000000000`, `1000000000001`, `1000000000002` проще вычислить, если сначала вычесть общую большую часть.

Поэтому в `statistics.c` первое значение сохраняется в `origin`, и для обновления моментов используется `x - origin`. В конце `origin` добавляется обратно только к среднему. Это математически эквивалентное преобразование: центральные моменты \(M_2\), \(M_3\), \(M_4\) от сдвига всех данных не меняются.

Внутренние вычисления проводятся в `long double`, что даёт дополнительный запас точности в GCC/MinGW. Напечатанные результаты относятся к типу `double`: если величина не может быть представлена в `double` без переполнения или исчезновения ненулевой дисперсии при округлении, программа сообщает об ограничении диапазона.

## 5. Компиляция и запуск в Windows (Git Bash)

Компилятор: GCC/MinGW-w64 (на вашей системе ранее использовался GCC 15.2.0).

Перейдите в папку `Task3`, содержащую файлы проекта.

**Сборка:**

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c statistics.c -lm -o program.exe
```

**Запуск для файла `example_data.txt`:**

```bash
./program.exe example_data.txt
```

Результат:

```text
Count: 3
Mean: 2
Variance (N-1): 1
Standard deviation: 1
Skewness: 0
Excess kurtosis: -2.3333333333333335
```

Другой файл передаётся первым аргументом командной строки:

```bash
./program.exe data.txt
```

Если путь содержит пробелы, возьмите его в кавычки:

```bash
./program.exe "my measurements.txt"
```

Данные должны быть текстовыми числами через пробелы или переводы строки; рекомендуется **одно число в каждой строке**, как сказано в пособии. Для десятичных дробей используется **точка**. Заголовки, текстовые комментарии и значения `nan`/`inf` не допускаются.

Дополнительная возможность — чтение прямо из стандартного ввода без сохранения файла:

```bash
printf '1\n2\n3\n' | ./program.exe -
```

Здесь `-` означает, что числа берутся из `stdin`. Программа не перемещает указатель потока назад и может обрабатывать данные по мере поступления.

## 6. Автоматические тесты

### Модульные тесты

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic tests.c statistics.c -lm -o tests.exe
./tests.exe
```

Ожидаемый итог:

```text
Test groups: 8; checks: 79; failures: 0
```

| Группа | Примеры и ожидаемое поведение |
|---|---|
| 1. Простые значения | `1, 2, 3`: среднее `2`, дисперсия `1`, асимметрия `0`, эксцесс `−7/3`. |
| 2. Асимметрия | `0, 0, 0, 10`: асимметрия `+0.75`; отражённый набор `0, 10, 10, 10`: `−0.75`. Эксцесс одинаковый. |
| 3. Два значения | `1, 3`: дисперсия `2` по формуле с `N−1`, эксцесс `−2.75`. |
| 4. Сдвиг и масштаб | Большой общий сдвиг `10¹²` с маленькими отклонениями; умножение данных на коэффициент. |
| 5. Вырожденные данные | Пустой файл, только пробелы, одно значение, одинаковые значения. |
| 6. Ошибки данных | Неожиданный текст, `nan`, `inf`, переполнение числа, испорченная запись. |
| 7. Пределы типа `double` | Слишком большие и слишком маленькие ненулевые дисперсии; отсутствие молчаливой подмены на `inf` или `0`. |
| 8. Нормальное распределение | **100 000** воспроизводимых псевдослучайных значений с теоретическими `μ=5`, `σ²=4`. Проверяются среднее, дисперсия, близкие к нулю асимметрия и эксцесс. |

Нормальная выборка создаётся **внутри теста** с фиксированным начальным состоянием генератора и сохраняется во временный файл. В тесте проверяются *приближённые* значения: характеристика конкретной конечной случайной выборки необязательно точно совпадает с параметром исходного распределения.

## 7. Граничные случаи и ограничения

| Ситуация | Поведение |
|---|---|
| Файл пустой или содержит только пробелы | Ошибка: статистики не определены. |
| В файле ровно одно число (`N=1`) | Среднее выводится; дисперсия, стандартное отклонение, асимметрия и эксцесс отмечаются `undefined`. |
| `N>=2`, все значения одинаковы | Дисперсия и стандартное отклонение равны нулю; асимметрия и эксцесс не определены из-за деления на `σ=0`. |
| `N=2`, значения различаются | Все указанные величины вычисляются строго по формулам пособия. |
| Нечисловой токен, `NaN`, бесконечность, число с переполнением | Ошибка ввода вместо частичного результата. |
| Файл отсутствует или недоступен | Сообщение об ошибке открытия файла. |
| Ненулевая дисперсия не помещается в `double` либо округляется до нуля | Явная ошибка диапазона вместо неверного численного результата. |
| Файл слишком велик для счётчика `unsigned int` | Явная ошибка вместо переполнения счётчика. |

**О точности:** алгоритм использует `long double` внутри, но сам формат входных и отображаемых чисел — `double`. Очень близкие огромные числа могут стать одинаковыми уже на стадии чтения (`double` не различает любые бесконечно близкие значения). На MSVC `long double` обычно не точнее `double`; целевая среда этой работы — GCC/MinGW-w64.

Функции `fscanf`, `fopen`, `fclose` и обработка `EOF` взяты из стандартной библиотеки C. Консольный интерфейс избегает формата `%zu`, который ранее вызывал предупреждения в вашей конфигурации MinGW.

Задание 2.3 выполнено по формулам (2.17)–(2.20). Программа читает произвольное количество чисел из файла **без массива и за один проход**, выводит все математически определённые характеристики, обрабатывает вырожденные данные и проверяется отдельными модульными и консольными тестами.
