# Глава 2, задание 2.4 — численное интегрирование

## 1. Постановка задачи

Требуется написать и проверить три функции:

```c
typedef double (*finteg)(double);

double trapz(finteg f, double a, double b, int n);
double simpson(finteg f, double a, double b, int n);
double trapz_adapt(finteg f, double a, double b, double eps);
```

- `trapz` — формула трапеций **(2.21)**;
- `simpson` — специальная формула четвёртого порядка **(2.23)**;
- `trapz_adapt` — адаптивное уточнение формулы трапеций с повторным использованием ранее посчитанных значений.

**Важный момент:** название `simpson` предписано пособием, но её реализация
в этом задании должна соответствовать **(2.23)**, а не обычной составной
формуле Симпсона с чередующимися коэффициентами (2.22).

## 3. Математические алгоритмы

### 3.1. Метод трапеций (2.21)

Для `n` одинаковых интервалов шаг `h = (b-a)/n`, узлы `x_i=a+ih`.
Функция вычисляет

\[
T_n=h\left(\frac{f(x_0)}2+\sum_{i=1}^{n-1}f(x_i)
                      +\frac{f(x_n)}2\right).
\]

Формула точна для констант и линейных функций. При достаточно гладкой
функции погрешность имеет порядок `O(h²)`.

### 3.2. Метод с концевыми поправками (2.23)

В пособии дана формула четвёртого порядка **без чередования весов**:

\[
S_n=h\bigg[\frac38(f_0+f_n)+\frac76(f_1+f_{n-1})
   +\frac{23}{24}(f_2+f_{n-2})+\sum_{i=3}^{n-3}f_i\bigg].
\]

Она реализована в функции `simpson`. Для правильного разнесения
трёх пар крайних узлов необходимо `n >= 5` (при `n=5` внутренняя
сумма пуста). Для многочленов степеней `0`, `1`, `2`, `3` формула
даёт точное значение с учётом погрешности арифметики. Для
достаточно гладких функций ошибка уменьшается как `O(h⁴)`.

### 3.3. Адаптивные трапеции

Сначала считается интеграл `T_1` на одном интервале.
При делении всех существующих интервалов пополам старые узлы
сохраняются, новые значения функции требуются только в средних точках.
Поэтому используется рекуррентная формула

\[
T_{2n}=\frac{T_n}{2}+\frac{h}{2}
\sum_{i=0}^{n-1}f\left(a+\left(i+\frac12\right)h\right),
\quad h=\frac{b-a}{n}.
\]

Это основное требование к `trapz_adapt`: **ранее вычисленные узлы не
пересчитываются**. Например, для постоянной функции первое успешное
уточнение требует ровно три вызова `f`: два конца и один середина.

Критерий остановки в учебнике записан как `|q0 - q1| < eps*q0`.
Он непригоден при `q0 < 0` и нулевом интеграле. Простая замена
правой части на `eps * max(1, |q1|)` также неправильна для
маленьких интегралов: при `|q1| < 1` допуск становится абсолютным,
а **не относительным**, и метод может завершиться слишком рано.

Поэтому параллельно с `T_n` рассчитывается значение `A_n` —
трапециевидная оценка интеграла от модуля функции:

\[
A_n=|h|\left[\frac{|f(a)|+|f(b)|}{2}
              +\sum_{i=1}^{n-1}|f(x_i)|\right].
\]

Величина `A_n` обновляется без дополнительных вызовов `f`:

\[
A_{2n}=\frac{A_n}{2}+\frac{|h|}{2}
\sum_{i=0}^{n-1}\left|f\left(a+\left(i+\frac12\right)h\right)\right|.
\]

Использован масштабно-относительный критерий

\[
|T_{2n}-T_n|\le\varepsilon A_{2n}.
\]

Это обеспечивает одинаковое поведение при масштабировании интеграла
и допускает отрицательные значения `T_n` и обратные пределы (`|h|`
обеспечивает положительность `A_n`). Для функции, тождественно
равной нулю, `A_n = 0` и равные нулю приближения завершают расчёт.
При взаимном сокращении положительных и отрицательных вкладов
критерий остаётся определённым, хотя он не гарантирует заданную
**относительную ошибку самого знакопеременного интеграла**.

Установлен предел **22 уточнения**, чтобы несходящийся расчtт не
выполнялся бесконечно. При достижении предела возвращается `NAN`.

## 4. Сборка и запуск (Windows, Git Bash, GCC/MinGW)

Откройте терминал в папке `Task4` с файлами проекта.

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c integrals.c -lm -o program.exe
```

Запуск имеет вид:

```bash
./program.exe function a b n eps
```

Где:

- `function`: `one`, `x`, `x2`, `x3`, `sin`, `cos`, `exp`, `invquad`;
- `a`, `b`: конечные пределы интегрирования (`a > b` разрешено);
- `n`: целое число интервалов для первых двух методов, **не менее 5**;
- `eps`: требуемый порог для адаптивного метода, `0 < eps < 1`.

Пример для `x²`:

```bash
./program.exe x2 0 1 100 1e-9
```

Ожидаемый результат:

```text
Function: x2
Interval: [0, 1]
Intervals: 100; tolerance: 1e-09
Trapezoidal (2.21): 0.33334999999999998
Formula (2.23):    0.33333333333333331
Adaptive:          0.33333333348855376
```

Точный результат равен `1/3 ≈ 0.3333333333333333`.

Другие примеры:

```bash
./program.exe sin 0 3.141592653589793 100 1e-9
./program.exe invquad 0 1 100 1e-9
./program.exe x3 -2 3 50 1e-9
./program.exe one 2 5 5 1e-9
```

| Функция и границы | Точный интеграл |
|---|---:|
| `x2`, `[0,1]` | `1/3` |
| `sin`, `[0,π]` | `2` |
| `invquad`, `[0,1]` | `π/4` |
| `x3`, `[-2,3]` | `65/4 = 16.25` |
| `one`, `[2,5]` | `3` |

## 6. Граничные случаи и ошибки

Публичные функции оставляют учебные сигнатуры: возвращают `double`.
При ошибке возвращается **`NAN`**, а `errno` уточняет причину:

| Ситуация | Результат |
|---|---|
| `f == NULL`, `n <= 0`, `n < 5` для (2.23), некорректный `eps` | `NAN`, `errno = EINVAL` |
| `a` или `b` равны `NaN` или бесконечности | `NAN`, `errno = EINVAL` |
| Функция возвращает `NaN` или бесконечность в проверенной точке | `NAN`, `errno = EDOM` |
| Выход интеграла за диапазон `double`, исчезновение ненулевого результата при приведении к `double` | `NAN`, `errno = ERANGE` |
| Адаптивный метод не сошёлся за установленное число уточнений | `NAN`, `errno = ERANGE` |
| `a == b` при допустимых аргументах | Ноль без вычисления `f` |
| `a > b` | Знак интеграла меняется |

Используется `long double` для промежуточной арифметики и
компенсированное суммирование Ноймайера для ограничения накопления
ошибки округления. Рабочая точность аргументов и результата остаётся
`double`; на MSVC `long double` может совпадать с `double`.

**Ограничение численного метода:** гладкость и разрешающая способность
сетки важны. Адаптивный критерий основан на близости двух приближений,
а не на строгой математической оценке ошибки. Для разрывов, острых
пиков и высокочастотных колебаний он может остановиться преждевременно.
Например, для `sin²(2πx)` на `[0,1]` точный интеграл равен `0.5`,
но первые два трапециевидных приближения могут практически совпасть
из-за выбора узлов. Обновлённый критерий уменьшает вероятность
такой ошибки, но **не исключает ложную сходимость**. При необходимости
можно дополнительно требовать минимальное число уточнений сетки.
Неинтегрируемые особенности не поддерживаются. Если особенность в
конкретной точке не попала в сетку, программа не может обнаружить её
автоматически. Для таких задач нужны специализированные алгоритмы.
