# Раздел 2.1. Решение квадратных и кубических уравнений на C

Учебная работа по пособию Е. Д. Маренкова «Программирование на языке Си для решения физических задач» (НИЯУ МИФИ, 2025, стр. 35–38).

## Цель

1. Реализовать `eq2` по прямой формуле (2.2) и показать её потерю точности.
2. Реализовать `eq2_correct` по формулам (2.3)–(2.4), устойчивым к вычитанию близких чисел.
3. Расширить устойчивое решение квадратного уравнения на комплексные корни.
4. Реализовать `eq3` по формулам (2.6)–(2.13).
5. Проверить случаи с тремя действительными корнями кубического уравнения и с одной действительной и двумя комплексно-сопряжёнными корнями.

## Используемые алгоритмы

### 1. Обычная формула квадратного уравнения: `eq2`

Для уравнения `a*x^2 + b*x + c = 0` (`a != 0`) вычисляется дискриминант

`D = b*b - 4*a*c`

и корни:

`x1 = (-b + sqrt(D))/(2*a)`

`x2 = (-b - sqrt(D))/(2*a)`

Это намеренно **неустойчивый в некоторых случаях** вариант. Если `a=1`, `b=-1`, `c=1e-30`, то точные корни приблизительно равны `1` и `1e-30`, но в арифметике `double` прямой способ выдаёт `1` и `0`: маленькое слагаемое теряется при вычитании близких чисел.

### 2. Устойчивая формула: `eq2_correct`

Используется промежуточная величина:

`q = -0.5 * (b + sign(b)*sqrt(D))`

Затем корни вычисляются как:

`x1 = q/a`, `x2 = c/q`.

Знак выбирается так, чтобы сложение `b` с `sign(b)*sqrt(D)` не приводило к катастрофическому сокращению значащих цифр. Для `c=0` предусмотрен отдельный случай: корни `0` и `-b/a`. Внутренние промежуточные вычисления выполняются в `long double`; наружу возвращается `double`, как требует пособие.

Функции `eq2` и `eq2_correct` имеют **ровно те сигнатуры с `double *`, которые указаны в пособии**. При `D<0` действительных корней нет, поэтому обе записывают `NAN` в результаты.

### 3. Комплексные корни: `eq2_correct_complex`

В пособии предлагается дополнительно усовершенствовать `eq2_correct` для комплексных корней. Чтобы одновременно сохранить указанную автором сигнатуру `eq2_correct`, эта возможность вынесена в отдельную функцию:

```c
void eq2_correct_complex(double a, double b, double c,
                         double complex *x1, double complex *x2);
```

При `D>=0` возвращаются действительные корни с нулевой мнимой частью. При `D<0` вычисляются сопряжённые корни:

`x1,2 = -b/(2*a) +/- i*sqrt(-D)/(2*a)`.

Используются возможности `<complex.h>` из C99/C11.

В некоторых версиях заголовков MinGW-w64 отсутствует макрос `CMPLX`, несмотря на поддержку комплексных чисел. В начале `equations.c` предусмотрено его условное определение:

```c
#ifndef CMPLX
#define CMPLX(real, imag) ((double complex)((real) + (imag) * I))
#endif
```

Если стандартный `CMPLX` уже определён, запасной вариант не используется. Это устраняет ошибку компиляции `implicit declaration of function 'CMPLX'` без изменения математических алгоритмов.

### 4. Кубическое уравнение: `eq3`

Решается **приведённое** кубическое уравнение:

`x^3 + a*x^2 + b*x + c = 0`.

Сначала находятся величины по формуле (2.6):

`Q = (a*a - 3*b)/9`

`R = (2*a*a*a - 9*a*b + 27*c)/54`.

- Если `R^2 < Q^3`, используются тригонометрические формулы (2.7)–(2.10). Все три корня действительные.
- Если `R^2 >= Q^3`, используются формулы (2.11)–(2.13). Получается один действительный корень и комплексно-сопряжённая пара, которая **на границе** может стать парой совпадающих действительных корней.

В `eq3` для промежуточных величин также используется `long double`. Корни возвращаются через `double complex *`. Порядок выдачи корней не гарантируется как возрастающий.

## Сборка и запуск

Нужен компилятор C11, например GCC (Linux, Ubuntu, MinGW-w64 на Windows). На компьютере, где выполнялась работа, доступен **GCC 15.2.0 (x86_64-ucrt)** в `C:\mingw64\bin`, а терминал используется **Git Bash**. Если `gcc --version` показывает старую версию из `C:\mingw32-main`, в текущем сеансе Git Bash можно переключиться командой:

```bash
export PATH="/c/mingw64/bin:$PATH"
hash -r
gcc --version
```

Из папки проекта выполните:

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c equations.c -lm -o demo
./demo
```

Программа предложит:

- `1` — квадратное уравнение `a*x^2 + b*x + c = 0`;
- `2` — кубическое уравнение `x^3 + a*x^2 + b*x + c = 0`.

После выбора введите три коэффициента через пробел. Десятичный разделитель — **точка**, например `1 -1 1e-30`.

Пример для проверки точности (вариант `1`, затем коэффициенты `1 -1 1e-30`):

```text
eq2 (direct formula): x1 = 1, x2 = 0
eq2_correct (stable): x1 = 1, x2 = 1e-30
complex x1 = 1 +0i
complex x2 = 1e-30 +0i
```

Пример для кубического уравнения `x^3 - 1 = 0` (вариант `2`, коэффициенты `0 0 -1`):

```text
x1 = 1 +0i
x2 = -0.5 +0.8660254037844386i
x3 = -0.5 -0.8660254037844386i
```

## Запуск автоматических тестов

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic tests.c equations.c -lm -o tests
./tests
```

Если все проверки пройдены, программа завершится с кодом `0`. Если хотя бы одна проверка не прошла, тестовая программа напечатает `FAIL` и завершится с кодом `1`.

Тесты вызывают функции непосредственно, без ручного ввода. Полный перечень, ожидаемые результаты и критерии проверки приведены ниже, в этом README.

## Обработка особых случаев и ограничения

- `a=0` для квадратного уравнения означает, что уравнение не квадратное. Функции возвращают `NAN`; переход к линейному уравнению **не выполняется**.
- `D=0`: два совпадающих действительных корня; `D<0`: их обрабатывает только комплексная версия.
- Нулевые коэффициенты `b`, `c` обрабатываются без деления на ноль в устойчивом методе.
- Для нечисловых/бесконечных коэффициентов (`NAN`, `INFINITY`) возвращаются `NAN`-корни. Консольный интерфейс дополнительно отвергает такие входные данные.
- На произвольно экстремальных числах конечной точности гарантировать точность невозможно. Повышенная точность `long double` зависит от компилятора и платформы; на некоторых платформах она совпадает с `double`.
- Базовая `eq2` специально оставлена в виде из пособия, поэтому может терять точность и переполняться на больших коэффициентах. Для практических вычислений следует использовать `eq2_correct` / `eq2_correct_complex`.

## Организация автоматического тестирования

Тесты реализованы в отдельном файле `tests.c`, который содержит собственную функцию `main()`. Поэтому при сборке тестов **не нужно** подключать `main.c`: иначе в программе появятся две функции `main()`.

Каждый сценарий запускается через макрос `RUN_TEST`. Внутри сценария вызывается проверяемая функция и сравниваются фактические корни с ожидаемыми. Если условие выполнено, выводится `[PASS]`, иначе — `[FAIL]` с пояснением. Результат каждого сценария влияет на общий счётчик ошибок.

### Критерии успешности

1. **Сравнение вещественных корней.** Используется проверка вида `|actual - expected| <= abs_tol + rel_tol * |expected|`. Для обычных тестов допуск составляет порядка `1e-12`–`1e-13`.
2. **Очень малый корень.** В сценарии с `1e-30` применяется относительный допуск `1e-12` и абсолютный `1e-40`, чтобы проверить сохранение значащих цифр, а не просто близость к нулю.
3. **Сравнение комплексных корней.** Используется расстояние `cabs(actual - expected)` с учётом масштаба ожидаемого комплексного значения.
4. **Порядок корней.** Результат считается правильным независимо от того, в каком порядке функция вернула корни; для кратных корней учитывается их количество.
5. **Проверка подстановкой.** Во всех тестах кубических уравнений (№ 10–14) каждый найденный корень `z` подставляется в `z³ + az² + bz + c`. Модуль невязки должен укладываться в масштабированный допуск `1e-11`.
6. **Код завершения.** Если ошибок нет, `tests.exe` возвращает `0`; иначе — `1`. В Git Bash результат проверяется командой `echo $?` сразу после запуска тестов.

## Вывод по работе

Реализованы прямая и устойчивая формулы решения квадратного уравнения, расширение на комплексные корни и решение приведённого кубического уравнения. На примере `a=1`, `b=-1`, `c=10^-30` показано, почему прямая формула теряет малый корень и как формула через `q` позволяет его сохранить. Проверены три действительных, комплексно-сопряжённые, кратные и нулевые корни кубического уравнения. Программная логика и результаты тестирования задокументированы в одном файле `README.md`.
