Учебная работа по пособию Е. Д. Маренкова «Программирование на языке Си для решения физических задач» (НИЯУ МИФИ, 2025, стр. 35–38).

## Цель

1. Реализовать `eq2` по прямой формуле (2.2) и показать её потерю точности.

5. Проверить случаи с тремя действительными корнями кубического уравнения и с одной действительной и двумя комплексно-сопряжёнными корнями, включая пограничные ситуации за пределами примеров пособия.

## Используемые алгоритмы

### 1. Обычная формула квадратного уравнения: `eq2`

Для уравнения `a*x^2 + b*x + c = 0` (`a != 0`) вычисляется дискриминант

`D = b*b - 4*a*c`

и корни:

`x1 = (-b + sqrt(D))/(2*a)`

`x2 = (-b - sqrt(D))/(2*a)`

Это намеренно **неустойчивый в некоторых случаях** вариант. Если `a=1`, `b=-1`, `c=1e-30`, то точные корни приблизительно равны `1` и `1e-30`, но в арифметике `double` прямой способ выдаёт `1` и `0`: маленькое слагаемое теряется при вычитании близких чисел.

### 2. Устойчивая формула: `eq2_correct`

Используется промежуточная величина:

`q = -0.5 * (b + sign(b)*sqrt(D))`

Затем корни вычисляются как:

`x1 = q/a`, `x2 = c/q`.

Знак выбирается так, чтобы сложение `b` с `sign(b)*sqrt(D)` не приводило к катастрофическому сокращению значащих цифр. Для `c=0` предусмотрен отдельный случай: корни `0` и `-b/a`; для `b=0` корни находятся как `±sqrt(-c/a)`, без образования очень малого произведения `a*c`. Внутренние промежуточные вычисления выполняются в `long double`; наружу возвращается `double`, как требует пособие.

Сам дискриминант тоже может терять точность при вычитании почти равных произведений `b²` и `4ac`. Поэтому `eq2_correct` и `eq2_correct_complex` используют общую вспомогательную функцию `quadratic_discriminant`: она получает старшие части произведений обычным умножением, а потерянные младшие части — через `fmal`, выполняющую умножение и сложение с единственным округлением. Так сохраняется, например, очень малый положительный дискриминант `4·2^-104` для коэффициентов `a=1+2^-52`, `b=-2`, `c=1-2^-52`. Учебная `eq2` намеренно не изменена.

Функции `eq2` и `eq2_correct` имеют **ровно те сигнатуры с `double *`, которые указаны в пособии**. При `D<0` действительных корней нет, поэтому обе записывают `NAN` в результаты.

### 3. Комплексные корни: `eq2_correct_complex`

В пособии предлагается дополнительно усовершенствовать `eq2_correct` для комплексных корней. Чтобы одновременно сохранить указанную автором сигнатуру `eq2_correct`, эта возможность вынесена в отдельную функцию:

```c
void eq2_correct_complex(double a, double b, double c,
                         double complex *x1, double complex *x2);
```

При `D>=0` возвращаются действительные корни с нулевой мнимой частью. При `D<0` вычисляются сопряжённые корни:

`x1,2 = -b/(2*a) +/- i*sqrt(-D)/(2*a)`.

Используются возможности `<complex.h>` из C99/C11.

В некоторых версиях заголовков MinGW-w64 отсутствует макрос `CMPLX`, несмотря на поддержку комплексных чисел. В начале `equations.c` предусмотрено его условное определение:

```c
#ifndef CMPLX
#define CMPLX(real, imag) ((double complex)((real) + (imag) * I))
#endif
```

Если стандартный `CMPLX` уже определён, запасной вариант не используется. Это устраняет ошибку компиляции `implicit declaration of function 'CMPLX'` без изменения математических алгоритмов.

### 4. Кубическое уравнение: `eq3`

Решается **приведённое** кубическое уравнение:

`x^3 + a*x^2 + b*x + c = 0`.

Сначала находятся величины по формуле (2.6):

`Q = (a*a - 3*b)/9`

`R = (2*a*a*a - 9*a*b + 27*c)/54`.

- Если `R^2 < Q^3`, используются тригонометрические формулы (2.7)–(2.10). Все три корня действительные.
- Если `R^2 >= Q^3`, используются формулы (2.11)–(2.13). Получается один действительный корень и комплексно-сопряжённая пара, которая **на границе** может стать парой совпадающих действительных корней.

Первоначально вычисленные по этим формулам корни **не всегда достаточно точны**. Например, для уравнения с корнями `-1`, `1` и `10^10` формулы Кардано могут потерять два малых корня. Поэтому после вычисления начального приближения добавлены следующие шаги:

1. **Выбор действительного корня.** Из первоначальных действительных приближений выбирается корень наибольшего модуля. При сильном различии масштабов это помогает выделить большой корень, не потеряв малые.
2. **Уточнение методом Ньютона.** Для выбранного корня `r` несколько раз применяется поправка `r = r - f(r)/f'(r)`, где `f(x)=x³+ax²+bx+c` и `f'(x)=3x²+2ax+b`. Если производная равна нулю или вычисление перестаёт быть корректным, уточнение останавливается.
3. **Сведение к квадратному уравнению.** После выделения множителя `(x-r)` оставшиеся корни находятся из `x² + d*x + e = 0`. Возможны два выражения для линейного коэффициента: `d=a+r` и, по формулам Виета, `d=(e-b)/r`, где `e=-c/r` (при `r≠0`). **Оба выражения могут терять точность**: первое при почти противоположных `a` и `r`, второе при близких `e` и `b`. Поэтому программа сравнивает оценку степени сокращения значащих цифр для двух разностей и выбирает более устойчивый вариант. Фиксированный порог `0.01`, способный исправлять одни примеры и портить другие, не используется. Оставшееся квадратное уравнение решается устойчивым способом.
4. **Контроль невязки.** Для каждого результата вычисляется относительная невязка `|f(z)|/(|z|³+|a||z|²+|b||z|+|c|)`. При её увеличении алгоритм дополнительно ищет действительный корень методом бисекции и сравнивает качество двух наборов корней.

В `eq3` для промежуточных величин используется `long double`. Корни возвращаются через `double complex *`. Уточнение не отменяет формулы пособия: они остаются отправной точкой вычислений. Порядок возвращаемых корней не гарантируется.

## Обоснование реализации и соответствия методичке

### Почему `eq3` не ограничивается формулами (2.6)–(2.13)

**Что выполнено буквально:** функция принимает три действительных коэффициента приведённого кубического уравнения и возвращает три значения типа `double complex` через указатели. Внутренняя функция `cubic_cardano` реализует вычисление `Q` и `R` по (2.6), ветвление по `R² < Q³`, тригонометрические выражения (2.7)–(2.10) и выражения (2.11)–(2.13). В обоих случаях вычисляются начальные приближения всех трёх корней.

**Что является дополнением:** итоговые корни `eq3` получает после уточнения одного действительного приближения методом Ньютона, деления многочлена на `(x-r)` и решения оставшегося квадратного уравнения. При большой невязке предусмотрен запасной поиск действительного корня методом бисекции. Поэтому нельзя утверждать, что *окончательные* корни всегда непосредственно возвращаются по (2.7)–(2.13) без изменения: это расширенная численная реализация алгоритма из пособия.

Дополнительные шаги нужны из-за арифметики с конечной точностью:

1. **Потеря малых корней.** В формулах Кардано встречается вычитание близких больших величин. Когда один корень порядка `10^10`, а остальные `±1`, малые корни могут быть вычислены как нули. Уточнение большого корня с последующим сведением к квадратному уравнению позволяет сохранить малую пару.
2. **Уточнение Ньютона.** Для действительного корня применяется `r <- r - f(r)/f'(r)`. Метод улучшает приближение, если производная и промежуточные результаты конечны и производная не равна нулю. Число шагов ограничено 40, поэтому бесконечного цикла нет. При нулевой производной или отсутствии дальнейшего изменения числа итерации прекращаются.
3. **Дефляция без лишней потери точности.** Точное алгебраическое разложение имеет вид:

   ```text
   x³ + a*x² + b*x + c = (x-r)*(x² + d*x + e)
   a = d-r,       b = e-r*d,       c = -r*e
   d = a+r,       e = -c/r,        d = (e-b)/r   (при r != 0)
   ```

   Это не новая математическая задача: корни квадратного множителя являются двумя оставшимися корнями исходного кубического уравнения. Соотношения Виета дают два способа вычислить `d`, но ни один не является безусловно лучшим. Поэтому сравниваются показатели сокращения значащих цифр:

   ```text
   k1 = (|a| + |r|)/|a+r|
   k2 = (|e| + |b|)/|e-b|
   ```

   Предпочтение отдаётся выражению с меньшим показателем; в коде не требуется буквально делить на почти нулевые разности — сравниваются эквивалентные произведения. Если вариант через `r` недопустим, используется исходное выражение. Фиксированный порог переключения `0.01` не подходит: он улучшает один пример, но ухудшает другой.
4. **Запасная бисекция.** Кубический многочлен с действительными коэффициентами и старшим коэффициентом `1` имеет хотя бы один действительный корень. Если первоначальный набор корней показывает слишком большую нормированную невязку, можно найти альтернативный действительный корень бисекцией на ограничивающем интервале, уточнить его и повторить дефляцию. В реализации ограничено и число шагов бисекции (2048).

**Вывод о соответствии заданию:** формулы (2.6)–(2.13) присутствуют и применяются, сигнатура `eq3` соответствует пособию, требуемые два типа кубических уравнений обрабатываются. Дополнительные методы служат исправлению численных ошибок. Если преподаватель требует *только буквальную* реализацию формул без дополнительных шагов, эту версию следует представлять как численно улучшенный вариант, а для строгого сравнения можно отдельно выделить `eq3_cardano`, возвращающую непосредственно результаты `cubic_cardano`. В рамках текущего задания отдельная демонстрационная функция не добавлялась, чтобы не дублировать решение и не менять обязательный интерфейс.

### Почему нельзя ограничиться обычным дискриминантом

Формула через `q` защищает от потери малого корня при вычислении `-b ± sqrt(D)`, но не исправляет ошибки, которые уже возникли при вычислении `D = b*b - 4*a*c`. Например, при `a=1+2^-52`, `b=-2`, `c=1-2^-52` точный дискриминант положителен и равен `4*2^-104`. Обычные промежуточные умножения даже в `long double` могут округлиться так, что получится `D=0`, хотя корни `1` и `c/a` различимы в `double`.

Вспомогательная функция `quadratic_discriminant` использует `fmal` для нахождения младших частей произведений. Таким образом, сначала устраняется ошибка образования дискриминанта, затем применяется устойчивая формула через `q`. **Функция `eq2` оставлена неустойчивой специально**, поскольку задача требует сравнить исходную формулу с улучшенной на коэффициентах `1`, `-1`, `1e-30`.

### Почему используются `long double` и GCC/MinGW-w64

Основной тип входных и выходных вещественных значений — `double`: это следует из обязательных сигнатур функций. `long double` используется только для внутренних вычислений, чтобы уменьшить округление промежуточных произведений, сумм, дискриминантов и значений многочленов. Повышенная точность особенно полезна при работе с коэффициентами разных порядков.

**Целевая среда проекта:** Windows, Git Bash, MinGW-w64, GCC 15.2.0 (`x86_64-w64-mingw32`, каталог `C:\mingw64\bin`). Исходный код использует стандарт C11, комплексную арифметику из `<complex.h>` и математические функции из `<math.h>`; при линковке необходим `-lm`. Именно в этой конфигурации предполагается собирать и сдавать работу. В проведённых проверках использовался GCC в Linux; прогон на пользовательском MinGW-w64 выполняется по командам ниже.

Ограничения переносимости:

- В GCC для обычной x86-64-конфигурации `long double` использует расширенную точность x87 (80-битный формат с 64 значащими двоичными битами; размер хранения может быть 16 байт из-за выравнивания). Однако стандарт языка C не гарантирует, что `long double` точнее `double` на любой платформе.
- В компиляторе **MSVC `long double` представлен как `double`**, то есть дополнительная точность и диапазон экспоненты исчезают. Поэтому тесты с экстремально большими/малыми коэффициентами могут работать иначе.
- У MSVC есть и отдельное ограничение: его реализация `<complex.h>` использует структуры и не поддерживает обычные арифметические операции над комплексными числами в том же виде, что GCC. Полноценная поддержка MSVC потребовала бы отдельных изменений работы с комплексными значениями. Она **не входит в требования этой лабораторной** и не необходима для выбранного GCC/MinGW-w64.

Проверить, какой `gcc` используется в Git Bash, можно командами `which gcc`, `gcc --version`, `gcc -dumpmachine`. При необходимости характеристики типов `double` и `long double` можно посмотреть через макросы `DBL_MANT_DIG`, `LDBL_MANT_DIG`, `DBL_MAX_EXP`, `LDBL_MAX_EXP` из `<float.h>`. Проверка только `sizeof(long double)` недостаточна: размер хранения не равен числу значащих битов.

**Решение о переносимости:** не снижать точность алгоритма ради MSVC и не переводить учебную программу на C++. Наша задача — корректное решение на языке C в выбранном и проверяемом окружении GCC. При необходимости работы на MSVC потребуется отдельный этап портирования и повторного тестирования.

Официальные справочные материалы:

- [GCC: опции x86 и формат `long double`](https://gcc.gnu.org/onlinedocs/gcc/x86-Options.html).
- [Microsoft Learn: тип `long double` в MSVC](https://learn.microsoft.com/en-us/cpp/c-language/type-long-double?view=msvc-170).
- [Microsoft Learn: поддержка комплексной арифметики C](https://learn.microsoft.com/en-us/cpp/c-runtime-library/complex-math-support?view=msvc-170).

## Обработка особых случаев и ограничения

- `a=0` для квадратного уравнения означает, что уравнение не квадратное. Функции возвращают `NAN`; переход к линейному уравнению **не выполняется**.
- `D=0`: два совпадающих действительных корня; `D<0`: их обрабатывает только комплексная версия.
- Нулевые коэффициенты `b`, `c` обрабатываются без деления на ноль в устойчивом методе.
- Очень маленький, но положительный дискриминант не приравнивается к нулю из-за округления промежуточных произведений; для его вычисления используется `fmal`.
- Проверены коэффициенты порядка `10^200`, субнормальные числа порядка `5·10^-324`, близкие и кратные корни, а также кубические уравнения с корнями существенно различающихся порядков (вплоть до `10^300`).
- Для нечисловых/бесконечных коэффициентов (`NAN`, `INFINITY`) возвращаются `NAN`-корни. Консольный интерфейс дополнительно отвергает такие входные данные.
- Передаваемые указатели для результатов должны быть корректными и указывать на **разные** переменные. При `NULL` функция прекращает выполнение, не записывая результат.
- При математически кратных или почти кратных корнях малые изменения коэффициентов могут сильно менять сами корни. Малая невязка подстановки подтверждает согласованность вычисленного решения с уравнением, но **не гарантирует** малую относительную ошибку каждого корня. Если точный результат по модулю выходит за диапазон `double`, возможно получение бесконечности или нуля при преобразовании типа.
- На произвольно экстремальных числах конечной точности гарантировать точность невозможно. Повышенная точность `long double` зависит от компилятора и платформы; на некоторых платформах она совпадает с `double`. Реализация в первую очередь проверена с GCC, где `long double` имеет расширенную точность.
- Функция `fmal` входит в математическую библиотеку C99 и доступна в используемой сборке GCC/MinGW-w64; для линковки необходим ключ `-lm`.
- Базовая `eq2` специально оставлена в виде из пособия, поэтому может терять точность и переполняться на больших коэффициентах. Для практических вычислений следует использовать `eq2_correct` / `eq2_correct_complex`.

## Организация автоматического тестирования

Тесты реализованы в отдельном файле `tests.c`, который содержит собственную функцию `main()`. Поэтому при сборке тестов **не нужно** подключать `main.c`: иначе в программе появятся две функции `main()`.

Каждый сценарий запускается через макрос `RUN_TEST`. Внутри сценария вызывается проверяемая функция и сравниваются фактические корни с ожидаемыми. Если условие выполнено, выводится `[PASS]`, иначе — `[FAIL]` с пояснением. Результат каждого сценария влияет на общий счётчик ошибок.

### Критерии успешности

1. **Сравнение вещественных корней.** Используется проверка вида `|actual - expected| <= abs_tol + rel_tol * |expected|`. Для обычных тестов допуск составляет порядка `1e-12`–`1e-13`.
2. **Очень малый корень.** В сценарии с `1e-30` применяется относительный допуск `1e-12` и абсолютный `1e-40`, чтобы проверить сохранение значащих цифр, а не просто близость к нулю.
3. **Сравнение комплексных корней.** Используется расстояние `cabs(actual - expected)` с учётом масштаба ожидаемого комплексного значения.
4. **Порядок корней.** Результат считается правильным независимо от того, в каком порядке функция вернула корни; для кратных корней учитывается их количество.
5. **Проверка подстановкой.** Для числовых тестов квадратного и кубического уравнений корни подставляются в исходные многочлены. Кубическая невязка считается через `long double` и сравнивается с масштабированной величиной `1e-11*(|z|³+|a||z|²+|b||z|+|c|)`; это позволяет проверить и очень большие, и очень малые корни без искусственного смягчения допуска за счёт добавления `1`.
6. **Массовое тестирование.** С помощью генератора с фиксированным начальным значением создаётся 1000 кубических примеров с заранее известными корнями, а также 20 000 уравнений со случайными коэффициентами разных порядков. Последний сценарий проверяет относительную невязку каждого корня с порогом `10^-12`.
7. **Регрессионные примеры.** Тесты № 12, 28 и 29 сравнивают непосредственно сами корни (с очень малым или нулевым абсолютным допуском). Это важно: малая невязка сама по себе не всегда выявляет потерю малой части комплексного корня.
8. **Код завершения.** Если ошибок нет, `tests.exe` возвращает `0`; иначе — `1`. В Git Bash результат проверяется командой `echo $?` сразу после запуска тестов.

### Почему выбран именно такой способ проверки

- **Проверка известных корней** позволяет непосредственно увидеть разницу между правильным и ошибочным результатом. Её нельзя заменять одной лишь подстановкой корня в исходный многочлен.
- **Нормированная невязка** учитывает порядок величины коэффициентов и корня. Обычная абсолютная невязка `|f(z)|` не подходит для сопоставления уравнений с коэффициентами `1e-300` и `1e300`.
- **Обе ветви кубического решения** проверяются отдельно: три действительных корня и один действительный плюс комплексно-сопряжённая пара. Кратные и нулевые корни проверяются дополнительно.
- **Граничные случаи** (`a=0`, `b=0`, `c=0`, отрицательный или нулевой дискриминант, `NAN`, `INFINITY`, субнормальные числа) показывают, что функция не делит на ноль и соблюдает оговорённый контракт.
- **Стресс-тест с разными масштабами коэффициентов** исследует ошибки, которые могут не проявиться на нескольких подобранных вручную примерах. Воспроизводимый тест из `tests.c` содержит 20 000 наборов; исследовательский прогон на 2 млн наборов выполнялся отдельно и не входит в число 120 стандартных проверок.

Малая невязка не означает автоматически, что корень найден с такой же малой **прямой относительной ошибкой**. У почти кратного корня производная `f'(z)` мала, поэтому даже незначительная ошибка коэффициентов или вычислений может заметно сместить корень. Именно поэтому тесты сочетают сравнение с эталонными корнями и проверку подстановкой, а результат стресс-тестирования не интерпретируется как математическое доказательство безошибочности.

## Краткие ответы для защиты

**Почему в проекте две функции для действительных корней квадратного уравнения?** `eq2` реализует формулу (2.2) буквально и демонстрирует потерю точности; `eq2_correct` использует (2.3)–(2.4) и сохраняет малый корень на примере из задания. Это позволяет сравнить вычислительные свойства двух математически эквивалентных формул.

**Зачем добавлена `eq2_correct_complex`?** По условию требуется расширить программу на комплексные корни, но в языке C нельзя перегрузить функцию `eq2_correct` с прежними указателями `double *`. Поэтому оставлена обязательная функция с исходной сигнатурой и добавлена отдельная версия с `double complex *`.

**Почему в `eq3` используется Ньютон, если пособие приводит формулы Кардано?** Формулы (2.6)–(2.13) реализованы и дают начальные приближения. Уточнение предназначено исключительно для борьбы с накоплением ошибок округления, особенно когда величины корней сильно различаются. Классическое решение не заменено другим уравнением: оно уточняется, а оставшиеся корни находятся из алгебраически эквивалентного квадратного множителя.

**Почему нельзя всегда вычислять `d=a+r` либо всегда `d=(e-b)/r`?** В первом случае теряются цифры при `a≈-r`, во втором — при `e≈b`. Программа оценивает сокращение в обеих разностях и выбирает вариант с меньшей ожидаемой потерей точности. Два специальных регрессионных теста демонстрируют необходимость обоих вариантов.

**Зачем `long double` и `fmal`?** Первый тип уменьшает ошибки промежуточных вычислений в используемом GCC. Функция `fmal` позволяет восстановить младшие части произведений при вычислении очень малого дискриминанта. При этом интерфейс остаётся на `double`, как требуется в методичке.

**Почему программа не переносится специально на MSVC?** Целевая среда этой работы — GCC/MinGW-w64; она соответствует примерам сборки через GCC из пособия. В MSVC другая реализация `long double` и комплексной арифметики. Портирование было бы отдельной задачей, не относящейся к решению квадратных и кубических уравнений в данной лабораторной.

**Можно ли считать 34 пройденных теста гарантией правильности на любых числах?** Нет. Тесты подтверждают корректность проверенных случаев, в том числе крайних и случайных, но число `double` имеет конечные диапазон и точность, а почти кратные корни математически чувствительны к погрешности коэффициентов.

## Вывод по работе

Реализованы прямая и устойчивая формулы решения квадратного уравнения, расширение на комплексные корни и решение приведённого кубического уравнения. На примере `a=1`, `b=-1`, `c=10^-30` показано, почему прямая формула теряет малый корень и как формула через `q` позволяет его сохранить. Для устойчивого способа добавлено точное вычисление малого дискриминанта через `fmal`. Для кубического уравнения выполнены обе ветви формул Кардано, а численная реализация дополнена уточнением действительного корня и адаптивным выбором способа нахождения оставшейся пары. Проверены три действительных, комплексно-сопряжённые, кратные, нулевые и резко различающиеся по масштабу корни; программа и тесты описаны в одном файле `README.md`.
