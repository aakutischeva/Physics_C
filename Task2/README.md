# Глава 2, задание 2.2 — вычисление интегральной показательной функции

## 1. Постановка задачи

Написать на языке C функцию `double Ei(double x)`, вычисляющую интегральную показательную функцию при **`x > 0`**:

\[
\operatorname{Ei}(x) = \operatorname{PV}\int_{-\infty}^{x}\frac{e^t}{t}\,dt.
\]

Для разных значений `x` использовать два представления из пособия:

- **Формула (2.15), малые `x`:** сходящийся ряд.
- **Формула (2.16), большие `x`:** асимптотическое разложение.

Также требуется:

1. Выводить значение `Ei(x)` для заданного пользователем `x`.
2. Формировать файл `ei.dat` с двумя столбцами `x` и `Ei(x)`.
3. Запрашивать у пользователя границы `xmin`, `xmax` и число точек.
4. Использовать предыдущий член ряда для вычисления следующего; предусмотреть ограничение числа итераций и критерий точности.

## 3. Математическая основа

### 3.1. Сходящийся ряд — формула (2.15)

Для относительно малых `x`:

\[
\operatorname{Ei}(x)=\gamma+\ln x+\sum_{k=1}^{\infty}\frac{x^k}{k\,k!},
\qquad \gamma\approx0{,}57721566490153286061.
\]

Слагаемые вычисляются последовательно, без вычисления степеней и факториалов:

\[
t_1=x,\qquad t_k=t_{k-1}\frac{x(k-1)}{k^2},\quad k\ge2.
\]

После добавления очередного слагаемого проверяется условие

\[
|t_k|\le \text{EPS}\cdot|S|,
\]

где `S` — текущая сумма. Модуль нужен, поскольку `Ei(x)` для части положительных `x` отрицательна. Если сумма близка к нулю, относительный критерий становится очень строгим; в этом случае выполнение ограничивается `MAXIT` итерациями.

### 3.2. Асимптотическое разложение — формула (2.16)

Для больших положительных `x`:

\[
\operatorname{Ei}(x)\sim\frac{e^x}{x}
\left(1+\frac{1!}{x}+\frac{2!}{x^2}+\frac{3!}{x^3}+\cdots\right).
\]

Члены в скобках вычисляются по рекуррентной формуле

\[
u_0=1,\qquad u_k=u_{k-1}\frac{k}{x}.
\]

**Это асимптотический, а не сходящийся ряд.** При фиксированном `x` члены сначала уменьшаются, а затем начинают расти. Поэтому безусловное суммирование до 100 слагаемых может существенно испортить ответ.

В реализации суммирование прекращается, когда *следующий* член становится больше предыдущего: достигнут минимальный член асимптотического ряда. Результат принимается, если этот минимальный член не превышает `EPS`; иначе используется сходящийся ряд (2.15).

### 3.3. Переключение между способами

В пособии предложена оценочная граница

\[
x_\text{switch}=|\ln(\text{EPS})|\approx16{,}1181.
\]

Она используется как **нижняя граница для попытки** асимптотического вычисления:

- При `x < |ln(EPS)|` всегда применяется сходящийся ряд.
- При `x >= |ln(EPS)|` пробуется асимптотический ряд.
- Если минимальный член асимптотического ряда больше `EPS`, результат получается из сходящегося ряда.

Это небольшое уточнение учебного алгоритма обусловлено точностью: например, вблизи `x = 18` асимптотическое приближение ещё недостаточно точное при `EPS = 1e-7`.

### 3.4. Константы и точность

В `ei.c` заданы параметры, предложенные в пособии:

```c
#define EULER 0.57721566490153286061L
#define MAXIT 100
#define EPS 1e-7L
```

Промежуточные расчёты выполнены в `long double`, а функция возвращает `double`, как требуется в задании. Для больших `x` выражение `e^x/x` вычисляется в эквивалентном виде `exp(x - ln(x))`: это позволяет избежать переполнения промежуточного значения `exp(x)` в части случаев, когда окончательный результат ещё помещается в `double`.

**Важно:** `EPS = 1e-7` — заданный параметр остановки, а не универсальная математическая гарантия точности для любых машинных чисел. Особенно осторожно следует интерпретировать *относительную* ошибку около нуля функции `Ei(x)`.

## 4. Сборка и запуск (Windows, Git Bash, MinGW-w64)

Пример соответствует использовавшемуся ранее **GCC 15.2.0 (MinGW-w64)**. Все команды вводятся из каталога проекта, где расположены `main.c`, `ei.c` и `tests.c`.

### Собрать программу

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic main.c ei.c -lm -o program.exe
```

### Запустить

```bash
./program.exe
```

Появится меню:

```text
Section 2.2: exponential integral Ei(x), x > 0
1 - evaluate Ei(x)
2 - save a table to ei.dat
Choice:
```

Вариант **1** — вычисление одного значения. Например, введите `1`, затем `1`. Результат:

```text
Ei(1) = 1.8951178138912728
```

Вариант **2** — запись таблицы. Например, введите `2`, затем одной строкой:

```text
1 5 5
```

Будет создан `ei.dat`: **5 точек** на отрезке `[1, 5]` с шагом 1. Каждая строка содержит ровно два числа, разделённых пробелом:

```text
1 1.8951178138912728
2 4.9542343406873224
3 9.9338324167327148
4 19.630874323578201
5 40.18527478996041
```

Числа выводятся с точностью до 17 значащих цифр (`%.17g`) и без заголовка, чтобы файл было удобно читать программами построения графиков. При повторном запуске режима 2 **существующий `ei.dat` перезаписывается**.

Точки равномерно распределяются между `xmin` и `xmax`, включая оба конца. При одной точке выводится только `xmin`. При `xmin = xmax` можно создать таблицу из повторяющихся `x`.

## 5. Автоматические тесты

### Сборка тестов

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic tests.c ei.c -lm -o tests.exe
./tests.exe
```

Ожидаемый результат на проверенной конфигурации:

```text
Test groups: 6; checks: 67; failures: 0
```

Тесты используют `tmpfile()` для проверки записи таблицы: они **не создают и не перезаписывают пользовательский `ei.dat`**.

### Какие случаи покрыты

| Группа | Что проверяется | Зачем |
|---|---|---|
| 1. Значения из справочника | `x` от `1e-12` до `700`; в том числе `0.1`, `1`, `5`, `10`, `16`, `18`, `19`, `20`, `30`, `40`, `100` | Корректность обоих способов и переходной области. Эталон — `scipy.special.expi`. |
| 2. Область определения и диапазон | `x = 0`, отрицательное число, `NaN`, `+∞`, `DBL_TRUE_MIN`, `710`, `717` | Неверные аргументы, очень маленький `x` и переполнение результата. |
| 3. Близость к нулю `Ei` | `x ≈ 0.3725074107813666` | Проверка **абсолютной** ошибки, когда относительная ошибка неинформативна. |
| 4. Таблица из трёх точек | `xmin=1`, `xmax=3`, `N=3` | Ровно две числовые колонки, равномерная сетка, значения функции, отсутствие лишних строк. |
| 5. Граничные параметры таблицы | `N=1`, `xmin=xmax` | Отсутствие деления на ноль и правильное количество строк. |
| 6. Некорректная таблица | Нулевые и отрицательные границы, перевёрнутый интервал, `NaN`, бесконечная граница, `N=0`, слишком большое `N`, `NULL` | Контроль ввода; при ошибке файл не заполняется. |

В тестах сравниваются числа с допусками: для эталонных значений используется относительный допуск `1e-7` и абсолютный `1e-12`. Эти допуски намеренно согласованы с `EPS` и не претендуют на достижение машинной точности `double`.

Дополнительно алгоритм сравнивался с `scipy.special.expi` на **30 000 значений**: логарифмической сетке, случайных `x` и плотной сетке около точки переключения. Максимальная наблюдавшаяся относительная ошибка там, где она определена и устойчива, составила примерно `7.91e-8`; превышений `1e-7` не выявлено. Эта дополнительная проверка проводилась отдельно, в `tests.c` встроены воспроизводимые фиксированные случаи.


## 6. Обработка ошибок и ограничения

- Разрешены только **положительные конечные значения** `x` в интерактивном режиме. Для неположительного `x` или `NaN` сама функция `Ei` возвращает `NAN`; для `+INFINITY` — `INFINITY`.
- Диапазон таблицы должен удовлетворять `0 < xmin <= xmax`, а число точек должно быть от `1` до `1 000 000`. Верхнее ограничение введено, чтобы случайно не создавать слишком большой файл; в пособии оно не задано.
- Открытие `ei.dat` и запись в него проверяются на ошибки (`fopen`, `fprintf`, `fclose`).
- Оба ряда суммируются не более чем за `MAXIT = 100` итераций.
- Если истинное `Ei(x)` слишком велико для `double`, результат будет `+INFINITY`. Это ограничение представления чисел, не отдельная особенность интеграла.
- `long double` в GCC/MinGW может давать дополнительную точность промежуточных вычислений. В MSVC `long double` обычно имеет точность `double`, поэтому строгая воспроизводимость последних цифр между компиляторами не гарантирована. Для этой работы основная целевая среда — **GCC/MinGW-w64**, как использовалось ранее.
- Для `x <= 0` вычисления сознательно не реализуются: в пособии явно ограничена область `x > 0`.

**Итог:** программа выполняет задания раздела 2.2, вычисляет `Ei(x)`, предоставляет проверяемую генерацию `ei.dat` и включает автоматическую проверку основных и дополнительных граничных случаев.
